# dsh-auto-effort —— 推理等级 auto + 精简化输出

**每一轮请求发出去之前判一次"这次要花多少推理"，落成该模型真正支持的 effort id。**
判定是纯规则：0 额外 token、0 额外往返。开关在输入栏右下角的「优化」图标里。

## 界面：优化图标 + 开关面板

输入栏底部（模型选择器左边）一个「优化」图标，点开是开关面板；再点图标、按 Esc、
或点面板外收起。

| 开关 | 作用 |
| --- | --- |
| 自动化推理等级 | 按任务轻重自动选择推理强度；关闭后完全不动你的选择 |
| 精简化输出 | 压掉开场白与复述，只留事实与下一步；任务内容一字不改 |

**内置模型选择器完全不被触碰**：推理等级列表只显示模型真正支持的等级
（off / low / high / max），没有插件塞进去的条目，也不改它的文字与勾。

### 加一个开关 = 不用改本插件一行代码

面板从宿主读一张登记表 `GET /dsh-auto-effort?switches=1`，每项描述一个开关：

```json
{ "id": "concise", "label": { "zh": "精简化输出", "en": "Concise output" },
  "hint": { "zh": "…", "en": "…" }, "endpoint": "/dsh-concise-output", "field": "enabled" }
```

任何插件只要实现同一个约定就会出现在面板里：

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `<endpoint>` | — | `{ "enabled": boolean }` |
| POST | `<endpoint>` | `{ "enabled": boolean }` | `{ "enabled": boolean }` |

读不到（没装、404、返回垃圾）的开关直接不显示，不会出现"点了没反应"的项。
本插件自己的端点同时提供 `enabled`（自动化推理等级）与 `concise`（精简化输出）。

## 判定：档位怎么算出来

一次判定由三部分决定：

1. **信号加权**：26 类信号（动手做事、问题、高要求、穷尽、代码/技术词、轻动词、
   比较/决策/影响类问句、路径/命令/URL/交付物/数字等），加权求和后分档：

   | 分数 | 档位 |
   | --- | --- |
   | ≤ 0 | off |
   | 1~3 | low |
   | 4~8 | high |
   | ≥ 9 | max |

2. **任务槽位（含糊短追问）**：一句"那块再收一下"自己没有信号，分量由**仍在进行的那件事**给。
   判"含糊"不枚举指代词，而是**缺少具体锚点**（无路径/命令/代码块/URL/交付物/步骤/数字）
   且短（≤40 词）、非问候收尾。任务槽位在下列条件下继承：最近判到 high/max、
   `age ≤ taskMaxAge`（默认 3 条用户消息）。闲聊只增龄不清空（"好的"之后"继续"仍是同一件事）；
   自带锚点的轻消息视为转向新事情，槽位作废。

3. **边界**：`minTier` / `maxTier` / `effortFloor` / `effortCeiling`，默认保守。

## 手选的档位绝不被改写

用户在列表里选了具体等级时，那是明确指令，插件**一个字节都不改**：不做判定、不加下界、
不受上界影响；`mode: pin` 时连判定都不做。"连手选值也交给判定"必须显式配置
`effortFloor: 'off'`——那是主动放弃这条保护。

（实测教训：`effortCeiling: adapter-default` 曾把用户手选的 low 压成模型默认的 off。
边界只该作用于**判定值**，不该作用于**人的指令**。）

## 开关什么时候生效

- 面板开关写宿主状态文件 `<DSH_HOME>/auto-effort.json`（`{ mode, armed, concise }`），
  重启后仍在。
- 精简化是系统提示词里的一段（`auto-effort:concise`，order 10200），**段落名必须唯一**：
  与别的插件撞名会被宿主拒绝注册，整个插件会被静默丢弃（实测症状：路由 404、图标消失）。
- 文本是函数，每次装配前重新求值；关闭时返回空串，宿主丢弃整段，不占 token。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `auto` | `auto` 判定 / `pin` 只保护手选 / `off` 完全不动 |
| `enabled` | `true` | 总开关（`false` 等于 `mode: off`） |
| `persist` | `true` | 面板开关是否落盘 |
| `minTier` / `maxTier` | `off` / `max` | 人为上下限 |
| `effortFloor` | `observed` | 手选值受保护；`off` 才放开；`adapter-default` 以模型默认档为下界 |
| `effortCeiling` | `max` | 人为上限；不设就是模型的最高档 |
| `taskMaxAge` | `3` | 任务槽位最多跨几条用户消息 |
| `conciseDefault` | `false` | 精简化**首次**装配时的默认值 |
| `log` | `true` | 每次判定打一行 info 日志 |

未知键会被**严格拒绝**（配置写错当场报错，不会静默失效）。

## 诊断端点

| 查询 | 作用 |
| --- | --- |
| `GET /dsh-auto-effort` | 运行档、生效边界、守卫安装情况、两个开关的状态 |
| `?switches=1` | 面板的开关登记表 |
| `?decisions=1` | 最近 20 次判定：请求原本档位 → 最终发给适配器的档位 |
| `?catalog=provider/model` | 那条路由的推理等级列表（确认插件没往里塞东西） |
| `?selection=1` | 宿主记录的会话选择：请求头档位 + 最近的 model/selection 事件 |
| `POST { enabled: bool }` | 开/关自动化推理等级 |
| `POST { concise: bool }` | 开/关精简化输出 |

## 排查：应用打开后一片空白 / 点不动

**先看日志，不要猜：** `~/Library/Logs/DeepSeek Harness/crash-*.log`。

若出现这两行，就是**端口被占**，与本插件无关：

```
DesktopHostFatalError: dsh: startup failed: 2 required plugins did not activate
  Error: listen EADDRINUSE: address already in use 127.0.0.1:19387
```

宿主固定用 19387。已有另一个宿主占着它（上次没退干净的实例，或 3 秒内连开两次）时，
新宿主绑定失败 → `webserver`（必需插件）激活失败 → 依赖它的 12 个插件进入
**waiting for services**（本插件只依赖 `webServer`，也在其中）→ 前端停在启动页。
日志会明确把这些插件列为"等待服务"，而不是"出错"。

处理：先退出所有实例，**等端口真空出来**，再启动一次。等端口这一步不能省。
（`~/.dsh/auto-effort-troubleshooting.md` 有可直接执行的步骤。）

本插件在最大负载下实测（12 个 bundle、armed 状态、并发 20 次重活出站）：探测请求
延迟 0.0006s、内存 203MB 不涨、CPU 2%。它不会让宿主卡死。

## 行为边界（改了什么、没改什么）

**会做的**：在请求发出前改写 `reasoningEffort`；把虚拟档位 `auto` 翻译成具体档位；
注入/移除精简化那一段系统提示词。

**不会做的**：不改消息、不改工具结果、不改系统提示词其它段落、不改采样参数、
不注册工具、不动模型目录、不碰内置选择器的 DOM。

**失败方向**：模型元数据读不到、判定抛错、状态读不出、盘写不了，一律**原样放行**
（退化成"没装"），绝不让请求失败。
